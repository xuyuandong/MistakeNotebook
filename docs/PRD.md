## 1. 产品摘要

学生错题本是一款帮助学生快速收集语文、数学、英语错题，并通过 AI 完成错误归因、薄弱知识点识别和针对性练习的个人学习工具。

产品的核心不是“存图片”，而是建立闭环：

```text
拍照交给豆包 → 导入豆包 JSON → 确认识别结果 → 记录当时的错误 → AI 分析 → 定期复习 → 针对性出题 → 作答反馈 → 更新掌握度
```

### 1.1 产品原则

1. **录入优先**：单题核对保存不超过 30 秒；批量录入一份试卷的额外成本控制在“一次复制粘贴”。
2. **人对事实负责，AI 提建议**：题目、答案、学科和知识点都允许修改；AI 不得静默覆盖用户内容。
3. **先闭环，再扩科目**：首版只支持语文、数学、英语。
4. **可追溯**：AI 分析和生成题必须记录模型、提示词版本、来源错题及用户修改。
5. **单人可维护**：MVP 不做社交、班级、老师后台、复杂积分体系和多 Agent 编排。

## 2. 用户与场景

### 2.1 目标用户

- 主要用户：小学六年级、初中、高中学生，日常使用电脑整理试卷和作业。
- 次要用户：家长，协助把作业交给豆包识别、完成导入和查看薄弱点。
- 暂不服务：学校统一采购、教师布置作业、班级排行榜。

### 2.2 核心场景

1. 学生或家长把作业照片发给豆包，豆包按固定模板识别题目并输出 JSON。
2. 学生把 JSON 粘贴或上传到本系统，系统校验后批量生成错题草稿，逐题核对保存。
3. 学生补录或修正自己的错误答案、正确答案以及“为什么错”；系统给出错误类型和知识点建议。
4. 学生在复习页查看到期错题，先重新作答，再查看解析。
5. 学生在智能练习中选择学科，系统基于学生画像自动选题或编题（可切换“出旧题/编新题”），作答后 AI 判分并更新画像。

## 3. 目标、非目标与成功指标

### 3.1 MVP 目标

- 支持“豆包 JSON 导入（粘贴或文件）”与手动文本录入两种录入方式。
- 形成结构化错题档案，而不只是保存作业照片或识别文本。
- AI 结合历史错题规律与学生画像主动归因，输出技术性、方法性、认知性三层建议。
- 支持三科薄弱点统计；智能出题可选学科与来源（历史错题/编新题），作答后 AI 判分并更新画像。
- 浏览器直接使用，并可安装为 PWA，桌面端无需单独维护安装包。

### 3.2 MVP 非目标

- 不做手机原生 App；移动网页只保证查看和简单复习。
- 不做登录注册与多用户；程序仅限学生自己家庭单机使用，打开即用。
- 不做教师端、班级、作业下发、排行榜和社交。
- 不做自动判卷整张试卷；识别与录入围绕豆包 JSON 草稿进行。
- 不做手写公式编辑器；首版使用 LaTeX 预览，识别存疑时回豆包侧对照照片核对。
- 不承诺 AI 生成题与解析 100% 正确；首版必须允许用户标记问题。
- MVP 不做原生 macOS 客户端和完整离线同步；若 PWA 无法满足系统集成需求，再评估原生包装。

### 3.3 北极星指标与质量指标

**北极星指标**：每周完成的“有效复习题数”，即用户提交答案并获得反馈的错题或变式题数量。

| 指标 | MVP 目标 | 说明 |
|---|---:|---|
| 单题录入完成率 | ≥ 80% | 开始导入后成功保存错题 |
| 单题核对保存中位时长 | ≤ 30 秒 | 从打开草稿到保存 |
| 导入字段可接受率 | ≥ 85% | 豆包识别的字段无需大改即可保存；需用真实样本测量 |
| 导入批次可解析率 | ≥ 95% | 豆包 JSON 一次通过导入校验的比例 |
| AI 标签采纳率 | ≥ 60% | AI 建议的错误类型/知识点被保留 |
| 生成题可用率 | ≥ 90% | 新题模式：通过自动校验且未被用户报告为错误 |
| 主观题判分可用率 | ≥ 90% | LLM 判定结果与学生自判/申诉改判的一致比例 |
| 7 日内首次复习率 | ≥ 40% | 新建错题后 7 日内至少复习一次 |

以上是产品目标，不是模型能力承诺；上线前需用至少 300 道真实题建立基线。

## 5. 功能需求

## 5.1 错题录入

### 5.1.1 输入方式

识题不在本系统内完成：人工把作业照片或资料交给豆包，豆包按版本化模板输出结构化 JSON。MVP 支持三种进入方式：

- 粘贴豆包输出的 JSON 数组文本（主路径，每个元素一道题）；
- 上传 `.json` 文件；
- 手动输入或粘贴题目文本，作为豆包不可用时的兜底。

默认限制：单次导入 JSON ≤ 512 KB、≤ 50 题；实际值由部署资源调整。本系统不接收图片或 PDF 原件，原图保留在豆包会话/用户相册中。

### 5.1.2 导入与核对流程

1. 在豆包中按模板识别作业照片，复制 JSON（录入页提供“复制豆包识题模板”入口）。
2. 粘贴或上传到本系统；系统确定性校验并按题生成草稿，导入不调用任何模型。
3. 校验失败时给出可定位的错误（题号、字段），用户回豆包重新生成或手改 JSON 后重试。
4. 进入逐题核对页：左侧豆包识别原文，右侧结构化表单，全部字段选填、可修改。
5. 点击保存；一道或多道确认后的题目进入“待分析”状态；空白题按“完全不会”处理，不强制补答。
6. 用户可以继续导入多批，完成后点击“更新学生分析”统一处理；不要求每保存一道题就调用文本模型。

若豆包输出的字段缺失、格式漂移或公式疑似转录错误，系统必须突出提示用户核对，不得假装识别成功。

### 5.1.3 结构化字段

| 字段 | 必填 | 来源 | 说明 |
|---|---|---|---|
| 学科 | 是 | 豆包 JSON/用户 | 语文、数学、英语；中文别名自动归一 |
| 题干 | 是 | 豆包 JSON/手动 | 支持 Markdown、LaTeX |
| 题型 | 否 | 豆包 JSON | 归一到选择、填空、解答、阅读；其他值标记“其他” |
| 选项 | 否 | 豆包 JSON/用户 | 选择题选项包含在题干文本中，导入不强制拆分；手工录入可结构化 |
| 我的答案 | 建议必填 | 豆包 JSON/用户 | 学生手写作答的转录；空字符串或缺失视为“完全不会” |
| 正确答案 | 否 | 豆包 JSON/用户/AI | AI 推断需明确标记“待确认” |
| 标准解析 | 否 | 豆包 JSON/用户/AI | 来自 standard_solution（卷面解析转写）；AI 生成内容需带标识 |
| 错误备注 | 否 | 豆包 JSON/用户 | 学生对错误的原始描述，选填；AI 可基于历史规律补充归因（带标识） |
| 录入时年级 | 否 | 当前年级快照 | 用于理解当时学习阶段和控制后续出题难度，不限制知识点 |
| 来源/章节 | 否 | 豆包 JSON/用户 | chapter 字段映射为来源章节；可补试卷名、日期 |
| 导入原文 | 是 | 系统 | 豆包 JSON 按批次存档，用于追溯；不含原图 |

### 5.1.4 豆包识题规则

- 豆包只负责转录和结构化（题干、选项、卷面答案、学生作答），不判断错误原因；归因由本系统的分析任务完成。
- 识题模板版本化（`doubao-template@N`），与导入校验契约联动；模板语义变更必须先通过 `evals/import/` 黄金集回归。
- 豆包识别错误（公式、手写字、题号）靠核对页纠正；系统以“导入原文”为追溯基准，不回传原图。
- 豆包不在系统控制范围内：它可能不按模板输出、识别错漏或臆造。系统必须用严格校验兜底，宁可拒绝导入也不臆测。

### 5.1.5 验收标准

- 可通过粘贴和文件导入 JSON；导入同步完成，不锁死页面。
- 校验失败时能看到具体错误位置；识别不清的字段留空而不是编造。
- 用户保存前能逐字段修改识别结果；导入原文、用户修订版分别保留，便于追溯。
- 空白题（学生未作答）可直接保存并进入分析，不强制补充答案。
- 重复导入相同 JSON 时给出提醒，不强制阻止。
- 删除导入批次只影响未确认草稿；已保存错题不受影响。

## 5.2 错题管理与 AI 分析

### 5.2.1 错题档案

每道错题详情包括：原题、用户错误答案、正确答案/解析、知识点、错误类型、AI 分析、复习记录、关联变式题和内容修订历史。

支持：

- 按学科、年级、知识点、错误类型、掌握状态、时间筛选；
- 搜索题干、来源和备注；
- 收藏、归档、删除、批量加标签；
- 导出为 Markdown/JSON；后续可增加打印版 PDF。

### 5.2.2 错误类型与 AI 主动归因

错误分析分两个维度：

**技术性（单题归因）**，使用有限枚举：

| 类别 | 例子 |
|---|---|
| 知识缺失 | 概念、公式、词义、语法规则不掌握 |
| 审题理解偏差 | 题意理解错误、条件遗漏、阅读误判 |
| 方法选择 | 解题策略不合适、步骤规划错误 |
| 计算基本功 | 运算错误、符号错误、逻辑跳步 |
| 表达规范 | 单位、格式、答题要点、拼写或语法表达 |
| 粗心/检查 | 抄错、看错、漏答、未检查 |
| 未确认 | 完全无依据时的兜底 |

**学习方法与习惯（画像级）**：缺少检查习惯、注意力问题、紧张、时间不足、疏于练习等。这类结论通常无法从单题看出，必须由 AI 汇总大量历史错题后总结。

AI 归因规则：

- 错误备注选填，很多题没有学生输入；AI 必须结合该生历史错题分布、复习情况和学生画像主动替学生归因，而不是等学生自我归因。
- 每条归因输出：主要/次要错误类型、证据（可关联历史错题）、置信度；基于画像规律的推断必须标注“画像推断”。
- 建议分三层输出：技术性建议（该知识点的补救与练习）、方法性建议（练习策略、检查流程、时间分配）、认知性建议（自我监控、归因习惯）。
- 学生可以纠正 AI 归因；纠正值优先进入后续分析上下文，旧版本保留。

### 5.2.3 数据驱动的知识概念

- 用户不选择教材，也不预先配置“应该学习”的知识点清单。
- 每录入一道错题，AI 从题目和错误中提取 1～5 个候选知识概念；第一次出现时建立概念，后续相似名称合并为别名。
- 概念来自真实错题证据，例如“二次函数顶点式”“定语从句关系代词”，而不是教材目录。
- 一个错题可关联多个概念，并标记主要概念、证据和置信度。
- 用户可以改名、合并、拆分或忽略概念；系统保留合并历史，避免同义标签失控。
- 没有错题或作答证据的概念不进入学生档案，系统不展示预设的完整知识树。
- 当前年级只影响出题难度、阶段性报告和历史权重，不把其他年级的相关错题排除在记忆之外；旧错题通过“毕业机制”退出复习（连续答对即毕业，见 6.3），通过“概念重逢复活”按证据回来，而不是按年级过滤。

### 5.2.4 掌握度

每个“学生 × 知识点”维护 0～100 的可解释分数和最近练习时间。MVP 使用简单加权规则，不上复杂机器学习：

- 初始 50；
- 原错题复习正确：小幅上调；错误：明显下调；
- 变式题首次独立答对：较大上调；
- 使用提示后答对：少量上调；
- 久未复习：仅降低“置信度/新鲜度”，不直接判定遗忘；
- 最近 10 次作答权重大于历史作答。

前端展示“薄弱 / 需巩固 / 基本掌握”，分数细节可展开查看，避免制造虚假精确感。

### 5.2.5 学习者长期记忆

系统必须持续汇总学生历史，而不是将每道错题彼此孤立分析。长期记忆包括：

- 各知识点的掌握状态、证据数量和最近练习；
- 重复出现的错误模式和典型误区；
- 已验证有效或无效的改进策略；
- 学习方法与习惯画像：检查习惯、注意力、紧张、时间管理、练习量等（AI 画像推断，可纠正）；
- 分学科的阶段性总结及其更新时间；
- 支撑每条结论的错题和作答记录。

每次分析只加载当前任务所需的相关历史，不向模型发送全部错题。AI 生成的长期结论必须可追溯、可由学生纠正、可被新证据推翻，并且不能替代原始错题和作答记录。

学生问题分析采用以下触发方式：

- 保存错题后只标记为“待分析”，不立即调用文本模型。一次导入拆出的多道题以及连续导入的多批题目可以一起处理。
- 录入页和错题库提供“更新学生分析”按钮；点击后处理当前全部待分析记录。
- 如果用户没有主动更新，系统每天自动检查一次；只有存在待分析记录时才创建后台任务。
- 学生补充或修改答案、正确答案、错误备注后，将该题重新标记为待分析。
- 打开“学习分析”页面只读取已保存的分析结果，不因查看页面而触发全量模型调用。
- 分析任务执行期间按钮显示进度并禁止重复创建；任务开始后新录入的题目留给下一次更新。

更新分为两类：

1. **批量题目分析**：一次更新任务读取当时全部待分析题目，并结合最新学生画像与历史统计。为控制上下文长度，服务端按每批最多 10 道拆分模型调用，但对用户表现为一次更新。
2. **增量统计**：每批题目分析完成后，用普通代码更新受影响知识点的样本数、错误类型和掌握状态。
3. **学生总结**：使用上一版总结、本次新增分析和最新结构化统计生成新版总结，不读取全部历史原题。

正常使用不进行全量 AI 重算。全量重建只用于数据修复、总结结构升级或用户删除大量历史资料；重建仍从数据库中的结构化记录生成，不把全部原始图片一次性发送给模型。

### 5.2.6 复习计划

MVP 使用固定间隔：1、3、7、14、30 天。答错则回到 1 天；答对进入下一间隔。用户可“稍后复习”或手动标记已掌握。

### 5.2.7 验收标准

- 保存错题后，即使 AI 任务失败，错题仍可正常查看和编辑。
- AI 建议与用户确认值视觉上可区分。
- 用户修改标签后，后续分析使用确认值，但保留旧版本。
- 新错题或作答会增量更新相关知识点和记忆，不重算全部历史。
- 打开学习分析页面不会产生新的模型费用；页面需显示总结更新时间、待分析题目数和最近一次任务状态。
- 学生可以查看长期总结的依据，并纠正不准确的记忆。
- 删除历史资料后，依赖该资料的记忆会失效或重新计算。
- 删除错题时同步处理导入原文存档和派生数据；审计记录不保存题目正文。

## 5.3 智能出题与练习

### 5.3.1 生成入口

- “智能出题”：先选学科（语文/数学/英语），可选题型、难度、题数；系统由 LLM 分析学生画像（掌握度、错题分布、复习情况）自动确定目标知识点，并展示选题理由。
- 来源开关：`出旧题`（默认，从历史错题中选题重做，题目真实可靠）/ `编新题`（LLM 依据薄弱点生成变式题，走校验流水线）。
- 依赖图形作答的题目（题干含“如图”等指涉或【依赖图形】标记）不参与出旧题/编新题，仅保留统计与归因；历史错题全部依赖图形时明确提示改用编新题。
- “基于这道错题出变式题”：从错题详情发起，固定编新题模式。
- 自定义：知识点、难度、题型、题数。

MVP 每次最多 10 题，默认 5 题。作文整篇自动评分、英语口语和听力题不在 MVP。

### 5.3.2 三科策略

| 学科 | MVP 重点 | 强制规则 |
|---|---|---|
| 数学 | 概念、计算、应用、几何变式 | 生成后必须进行可执行或第二遍模型校验；答案唯一性需检查 |
| 语文 | 字词、病句、古诗文、阅读理解 | 阅读题必须同时生成自包含材料；主观题提供评分要点而非唯一答案 |
| 英语 | 词汇、语法、完形、阅读、翻译 | 题目注明可接受答案；阅读材料和题目难度匹配年级 |

### 5.3.3 生成约束

以下约束仅适用于编新题模式；出旧题模式是确定性检索历史错题，不生成题目内容。

生成服务必须收到结构化约束：年级、学科、知识点、题型、难度、参考错题特征以及禁止照抄原题。输出采用固定 JSON Schema，包括题干、选项、答案、解析、知识点、难度、校验结果。

禁止：

- 直接复制有版权题库中的整套内容；
- 输出与所选年级明显不匹配的内容；
- 在学生作答前泄露答案；
- 将大模型自评当作绝对正确；
- 生成需要看图（几何图形、函数图象、统计图等）才能作答的题：图形条件必须用文字完整描述，不得出现“如图”等指向插图的表述（提示词约束 + 程序化丢弃双重防线）。

### 5.3.4 校验门槛

编新题模式生成的题目进入学生端前依次通过：

1. JSON Schema 和必填字段校验；
2. 内容安全与重复度检查；
3. 学科规则校验，例如选择题答案必须在选项内；
4. 数学题优先使用 SymPy/规则计算复核，不能复核时调用独立校验提示；
5. 不通过则自动重试一次；仍失败则丢弃该题，不凑数。

### 5.3.5 作答与反馈

- 客观题本地自动判定；主观题/解答题由 LLM 按标准答案与评分要点判分，输出判定（正确/部分正确/错误）、判定依据和简评。
- 主观题判分期间展示等待进度（含已等待秒数），期间输入与提交按钮禁用，防止重复提交；判分超时或失败时可自判兜底。
- 判分结果入库并更新掌握度与学生画像；学生可对判分结果申诉或自判改判，改判记录保留并进入后续分析上下文。
- 用户可选择“不知道”或使用提示；这会影响掌握度更新。
- 提交后显示答案、解析、来源知识点以及与原错题的联系。
- 允许报告“答案错误 / 题意不清 / 超纲 / 其他”。被报告题不再重复推荐。

### 5.3.6 验收标准

- 用户可按学科创建练习，并切换旧题/新题来源；能查看“为什么出这些题”的选题理由。
- 生成任务异步执行，离开页面后仍可查看状态。
- 不合格题不会展示；部分成功时展示实际题数并说明。
- 主观题提交后有明确的判分中状态；判分失败时可自判兜底。
- 作答记录会更新知识点掌握度、学生画像和下一次复习日期。
- 每一道生成题能追溯到知识点、来源错题、模型及提示词版本。

## 5.4 学习分析

MVP 只做能驱动行动的四个视图：

1. 薄弱知识点 Top 10：掌握状态、样本数、最近一次练习、开始练习按钮。
2. 错误类型分布：按最近 30 天展示，并可进入对应错题。
3. 复习完成情况：本周计划数、完成数、正确率和逾期数。
4. 学习方法画像：检查习惯、注意力、紧张、时间管理、练习量等 AI 结论，标注“画像推断”与置信度，学生可纠正。

当某知识点作答样本少于 3 次时，展示“数据不足”，不下强结论；学习方法类结论必须展示依据（关联错题）。

## 5.5 数据与使用边界

- 程序仅限学生自己家庭使用，免登录：部署后打开即用，数据存本机 SQLite。
- 不设计注册、多用户和角色；所有数据固定归属唯一本地用户。
- 支持导出个人数据和一键清空全部数据；清空是危险操作，需输入 `.env` 中 `APP_AUTH_TOKEN` 配置的解锁口令，未配置口令时清空功能锁定（防误删优先）。
- AI 设置中说明数据流向：作业照片只进入豆包（用户自行操作），题目文本进入本系统和文本模型供应商。
- 默认不使用学生内容训练模型；若未来需要，必须独立、明确地征得同意。
- 若未来需要公网部署或多人使用，必须先恢复鉴权、用户隔离与未成年人隐私条款（见第 10 节发布门槛）。

## 5.6 AI 模型配置

- 只配置一个模型槽位：`text_model` 负责错误分析与画像、学习记忆汇总、智能出题和作答判分；普通文本模型即可，无需多模态能力。
- 供应商固定为 DeepSeek、GLM、Kimi 三家，不提供任意供应商插件或模型市场。
- 题目识别不消耗本系统模型：由豆包在系统外完成（见 5.1）；本系统只解析其 JSON 输出，不接入视觉模型。
- 模型地址、模型名和密钥环境变量名写入服务端配置文件；密钥本身只放环境变量。
- 修改配置后重启服务生效。首版不做网页热切换、自动路由或自动故障转移。
- 每次 AI 任务记录实际供应商、模型名和 prompt 版本，便于定位结果差异。
- CC Switch 只可用于开发调试，不作为产品运行依赖。

## 6. 关键页面

### 6.1 快速录入页

- 首屏是大面积 JSON 粘贴框，旁边保留“上传 .json 文件”和“手动输入”两个入口。
- 提供“复制豆包识题模板”按钮，模板版本与导入校验契约绑定。
- 导入后先显示批次校验结果（题数、重复提醒、错误定位），再进入逐题草稿核对。
- 核对页采用“导入原文 + 编辑表单”，保存按钮始终可见。
- AI 分析不是录入的必填步骤；保存后先进入待分析队列，由主动按钮或每日任务批量补全。

### 6.2 错题详情页

- 默认先展示题目和用户当时答案；答案/解析折叠，避免复习时直接看到。
- AI 分析每一项都有“接受 / 修改 / 忽略”。
- 底部展示复习时间线和“生成变式题”。

### 6.3 今日复习页

- 一次只展示一道题。
- 复习节奏分学科可配（设置页）：答对进入下一档，答错/部分正确/放弃**原地不倒退**（避免挫败感）；默认数学 `1→10→30` 天（重思考轻记忆），语文/英语 `1→3→7→14→30` 天（字词记忆）。
- 到期判断为“到期日 ≤ 今天”：当天没做，晚些打开页面照常出现并标记逾期，不会丢题；下次到期从**实际完成日**起算。
- **毕业机制**：同一道错题连续 3 次复习“正确”（部分正确/答错/放弃会打断连续）后不再安排复习，从到期列表自然退出；毕业判定由作答事实源确定性推导，不是新的排期状态。
- **概念重逢复活（可选，默认关闭）**：设置页开关。开启后，AI 分析把新错题关联到某知识概念时，该概念下已毕业的旧错题按第 2 档（比新题的第 1 档缓、比末档维护节奏急）重新排期——旧题不按年级过滤，而是按“这个知识点又出了问题”的证据回来；复活后一次答对即再次毕业，答错则回到常规节奏。机制处于观察期，默认不启用。
- **归档退出复习**：错题归档时取消其未完成复习排期（保留历史供审计）；恢复归档不自动恢复排期，需等概念重逢复活或重新出现错误。
- 到期列表排除依赖图形的错题（缺图无法重做），其复习排期也不计入复习统计，避免永久“逾期”。
- 提交前不显示答案；支持草稿、提示和“不知道”。
- 主观题判分等待交互同 5.3.5（等待进度 + 防重复提交）。
- 完成后给出下一步：继续、查看同类错题、生成强化题。

## 7. 优先级与版本计划

### P0：MVP，建议 10～14 个业余周

- Web/PWA 基础框架（免登录，打开即用）；
- 豆包 JSON 导入（粘贴/文件）、导入批次与逐题草稿核对、手动录入兜底；
- 错题 CRUD、搜索筛选、导入原文存档；
- AI 主动归因（技术性 + 学习方法/习惯）、从错题发现和合并知识概念；
- 固定间隔复习；
- 智能出题（学科 + 旧题/新题开关）与主观题 LLM 判分；
- 数据导出和一键清空（口令解锁）。

### P1：MVP 后

- 批量草稿核对与批量确认；
- 画像驱动的周/月学习报告；
- 更完整的三科规则校验；
- 本地 Ollama/兼容接口配置；
- 打印版练习卷及答案；
- 基础使用统计和错误报告后台。

### P2：验证有持续使用后

- 若豆包人工中转成为主要使用摩擦，再评估直调视觉模型 API；
- 本地 OCR/VLM sidecar 一键安装；
- 移动端拍照优化；
- 家长只读视图；
- 跨学科概念关系和更智能的同义概念合并。

## 8. 取舍与明确不做

| 取舍 | 决策 | 原因 |
|---|---|---|
| 是否做原生 Mac 客户端 | MVP 否 | PWA 已覆盖桌面使用；签名、公证、更新和双端测试会增加维护量 |
| 数据库 | SQLite | 单实例、小规模产品最省运维；达到明确扩展条件再迁移 |
| 是否上向量数据库 | 否 | 初期用 SQLite FTS5、概念关联和指纹去重足够 |
| 是否做微服务 | 否 | 模块化单体更适合一人开发和部署 |
| 是否自动整卷切题 | 否 | 豆包整页识别 + 逐题核对已覆盖；自动切题的边界错误会让确认成本变高 |
| 识题方式 | 豆包人工中转 | 识题算力与费用由豆包侧承担，本系统零视觉模型成本与运维；代价是每次导入多一步人工复制 |
| 账号体系 | 免登录 | 仅限学生家庭单机使用；公网部署或多用户需求出现时必须先恢复鉴权 |
| 主观题判分 | LLM 判分 + 判定依据 + 可申诉 | 判分错误率不可接受时退回“仅客观题自动判定” |
| 是否自建 OCR/PDF 解析 | 否 | 系统只消费豆包 JSON，不解析图片/PDF |
| 是否接收作业原图 | 否 | 原图留在豆包会话/用户相册；系统只存 JSON 导入原文，缩小隐私面与存储 |
| 是否把产品做成 Skill | 否 | Skill 用于开发与评测；学生仍需稳定 UI、持久数据和复习流程 |
| 是否全自动分析 | 否 | 错误原因依赖学生当时思路，必须允许补充和确认 |
| 是否自建题库 | 否 | 版权和运营成本高；首版围绕用户错题生成新题 |

## 9. 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 豆包识别或公式转录错误 | 错题与解析失真 | 逐题核对页、LaTeX 编辑、豆包侧原图对照、真实样本评测 |
| 豆包不按模板输出 JSON | 导入失败、人工返工 | 模板版本化、导入前校验并给出可定位的错误信息、中文别名宽容归一 |
| 豆包产品形态变化 | 模板可能失效 | 模板与契约版本化解耦豆包 UI 变化；必要时再评估直调视觉模型 API |
| 生成题答案错误 | 伤害学习效果 | 规则/SymPy 校验、独立复核、用户举报、问题题下线 |
| AI 替学生归因不准 | 误导学习方向 | 置信度与证据展示、画像推断标记、学生可纠正、纠正值进入后续上下文 |
| LLM 主观题判分误差 | 掌握度失真 | 标准答案+评分要点输入、部分正确档位、学生申诉改判、判分一致率评测 |
| 模型 API 产生持续费用 | 成本随分析/出题调用量增长 | 识题费用由豆包侧承担；文本模型限流、批大小限制、结果缓存、预算告警 |
| AI 产生大量同义概念 | 学生档案碎片化 | 名称规范化、别名、合并历史和用户确认；不维护教材知识树 |
| 未成年人隐私 | 合规和信任风险 | 原图不出豆包、数据最小化、明确同意、导出删除、区域法律核对 |
| 单人维护时间有限 | 项目烂尾 | P0 严格限范围、托管基础设施、少依赖、无微服务 |

## 10. 发布门槛

- 使用真实的三科各 100 道题完成豆包识题模板评测与导入解析评测（可解析率、字段准确率）；
- 使用三科各 50 道生成题完成人工审核，严重答案错误率低于 1%；
- 主观题判分评测：三科各 50 份真实作答，LLM 判定与学生自判一致率达到目标；
- 关键路径自动化测试通过：导入、核对确认、保存、复习、生成、判分、删除、导出；
- 完成隐私政策、服务条款、模型数据去向说明；
- 建立数据库每日备份和一次恢复演练；
- 建立 AI/解析任务失败率、耗时、队列长度和用户报告监控。
